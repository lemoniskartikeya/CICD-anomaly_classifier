## 1. Overview

Track 3 is dedicated to Digital Forensics and Incident Response (DFIR) telemetry extraction, statistical entropy profiling, and machine learning-driven anomaly detection on CI/CD build execution logs. 

Modern continuous integration environments (such as GitHub Actions) frequently face sophisticated software supply chain attacks, including pull request target abuse, malicious dependency installation scripts, environment variable token exfiltration, and runner takeover. Because raw execution logs generated by CI/CD workflows are semi-structured, noisy, and high-volume, traditional signature-based detection mechanisms fail to identify obfuscated and zero-day attack patterns.

This repository provides an end-to-end telemetry and ML pipeline that:
- Ingests raw continuous integration build logs from benign and compromised runs.
- Extracts lexical, behavioral, network, and statistical characteristics (such as Shannon entropy).
- Trains and evaluates both unsupervised and supervised machine learning models to detect malicious builds with zero prior rule definitions.

## 2. Till-Date Progress and Milestone Deliverables

The current codebase reflects the completed milestones for Weeks 1 through 5 of the project implementation roadmap:

### Milestone 1: Baseline Telemetry and Dataset Construction
- Implemented automated benign log collectors (`download_benign_logs.py` and `generate_benign_logs.py`) to simulate authentic CI/CD runs across diverse environments (Python, Node.js, Docker, Rust, Go, release packaging).
- Ingested 50 baseline benign build logs representing regular build, test, and release tasks.
- Synthesized and cataloged 5 attack traces corresponding to critical CI/CD threat classes:
  - `attack_01_secret_exfil.log`: Token harvesting and external HTTP exfiltration.
  - `attack_02_reverse_shell.log`: Interactive shell establishment via netcat/bash.
  - `attack_03_dependency_poison.log`: Malicious pre/post-install script exploitation.
  - `attack_04_env_dump.log`: Environment variable reconnaissance and dumping.
  - `attack_05_pr_injection.log`: Pull request title command injection payload execution.

### Milestone 2: Shannon Entropy and Heuristic Feature Engineering
- Implemented `entropy.py` to calculate per-line Shannon entropy ($H = -\sum p_i \log_2 p_i$), effectively flagging encoded secrets, base64 payloads, and high-randomness tokens.
- Developed `feature_extractor.py` to convert unstructured raw stdout streams into a structured 20-dimensional numeric feature vector.
- Vectorized features include:
  - Line entropy metrics (average line entropy, maximum entropy, high-entropy line frequency).
  - Suspicious shell commands (`curl`, `wget`, `nc`, `bash -i`, `python -c`, `base64`, `openssl`, `eval`, `chmod +x`, `/tmp/`).
  - Network and environment indicators (raw IPv4 strings, non-whitelisted external URLs, sensitive environment variable accesses such as `$GITHUB_TOKEN` and `$AWS_*`).
  - Structural metadata (total log line count, failed step errors, step boundaries).

### Milestone 3: Model Training, Serialization, and Evaluation
- Implemented `classifier.py` training three distinct model architectures:
  - **Isolation Forest (Unsupervised):** Anomaly detector isolating out-of-distribution build traces without requiring prior attack labels.
  - **Random Forest (Supervised):** Ensemble decision forest for robust multi-feature classification and feature importance extraction.
  - **Logistic Regression (Supervised Baseline):** Standard scaled linear model serving as an analytical baseline.
- Persisted serialized model weights and feature scalers in `models/` (`isolation_forest.pkl`, `random_forest.pkl`, `logistic_regression.pkl`, `scaler.pkl`).

### Top 5 Informative Features (Random Forest Feature Importance)
1. `total_lines` (21.48%): Attack executions exhibit distinct execution lengths compared to standard test suites.
2. `run_step_count` (20.38%): Malicious steps alter the baseline structure of legitimate pipeline steps.
3. `suspicious_url_count` (12.90%): Outbound connections toward non-GitHub endpoints.
4. `cmd_curl` (12.37%): Invocation of HTTP transfer utilities for data staging and exfiltration.
5. `high_entropy_count` (10.55%): Frequency of encoded secrets and base64 payloads exceeding the 4.5 bit entropy threshold.

## 4. Integration with Other Project Tracks

This repository is designed with zero coupling during local development and seamless drop-in integration during system synthesis:

```
[ Track 1: Vulnerable Range ]          [ Track 2: PipelineGuard ]
  (Live Attack Workflows)                (Static AST Scanner)
             |                                     |
             | PR Execution Logs                   | Pre-commit Workflow
             v                                     | YAML Violations
+--------------------------------------------------+---------------+
|                                                                  |
|                      Track 3: DFIR Telemetry                     |
|                                                                  |
|   1. Ingestion: data/attack_logs/ <--- Member 1 raw build logs   |
|   2. Feature Extraction: feature_extractor.py                    |
|   3. Anomaly Inference: classifier.py                            |
|   4. Correlation: Static AST Findings + Runtime Anomaly Traces   |
|                                                                  |
+--------------------------------------------------+---------------+
                                                   |
                                                   v
                                        [ Attack-Defense Matrix ]
                                        (Comprehensive Evaluation)
```

### Integration Protocol with Track 1 (Attacker Fork & Vulnerable CI/CD Range)
- Track 1 deploys 5 intentional workflow vulnerabilities on GitHub Actions (`pull_request_target`, unpinned actions, script injection, runner compromise).
- **Handoff Mechanism:** Member 1 triggers the attack vectors and exports the resulting raw GitHub Actions build zip files.
- **Track 3 Action:** The unzipped `.log` files are ingested directly into `data/attack_logs/`. Running `feature_extractor.py` and `classifier.py` benchmarks the detection rate against live attack telemetry.

### Integration Protocol with Track 2 (`PipelineGuard` Static Analysis Tool)
- Track 2 performs static AST analysis on workflow YAML configurations to identify policy violations before code execution.
- **Handoff Mechanism:** Track 2 outputs a structured SARIF/JSON report specifying which workflow files are vulnerable.
- **Track 3 Action:** Track 3 correlates static rule violations with runtime execution anomalies. If a static flaw slips through or cannot be determined statically (such as runtime dependency confusion), Track 3 catches the anomaly dynamically at runtime, proving defense-in-depth.

## 6. Setup and Execution

### Prerequisites
- Python 3.10+
- Virtual environment (recommended)

### Installation
```bash
git clone https://github.com/lemoniskartikeya/track3-log-anomaly-classifier.git
cd track3-log-anomaly-classifier
pip install -r requirements.txt
```

### Re-extract Features from Raw Logs
```bash
python feature_extractor.py
```
This parses all `.log` files in `data/attack_logs/` and `data/benign_logs/`, computes entropy metrics and command occurrences, and writes the dataset to `outputs/features.csv`.

### Train Models and Evaluate Metrics
```bash
python classifier.py
```
This loads `outputs/features.csv`, performs train/test splitting, trains the classifiers, outputs classification reports and confusion matrices, and refreshes the artifacts in `models/`.
